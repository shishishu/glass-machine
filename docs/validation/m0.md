# M0 验证报告

本文件说明 M0 使用什么方法验证、这些证据能够证明什么。里程碑范围、交付清单和正式结论见 [M0 完成与验收报告](../milestones/m0-completion-report.md)。

## 验证对象

M0 选择 1 位四态 NOT 作为最小基础设施验证切片。它不是为了证明 NOT 本身有多复杂，而是为了验证从规格、模型、事件、轨迹、调试、实验、重放到可视化的完整基础设施能够闭环。M1 的一位全加器才是第一个面向体系结构学习的完整垂直切片。

## Ground truth 与独立模型

NOT 通过四条路径验证：

1. 测试中的四态真值表字面量；
2. 以不可变映射实现的 `ReferenceNot`；
3. 作为事件驱动组件实现的 `NotGate`；
4. 通过独立字符转换路径实现的 `FastNot`。

四个输入 `0`、`1`、`X`、`Z` 全部穷举比较。三套模型没有共同调用同一个 NOT 求值函数，因此差分比较不是同一算法的自我证明。

## 验证项目

自动测试覆盖：

- 四态 NOT 的全部输入；
- 非法逻辑字符和显式位宽错误；
- 独立运行之间的确定性轨迹摘要；
- 输入事件到输出事件的因果链接和声明延迟；
- JSONL 轨迹写入／读取后的相等性；
- 通过重新计算完成实验重放；
- 稳定态快照与恢复；
- 重复信号、重复组件、位宽和驱动冲突失败；
- 通过事件预算检测振荡或无法稳定；
- 事件单步、探针和信号断点；
- GUI controller 的状态来自同一份已提交仿真轨迹；
- CLI 验证入口。

## 验收命令


## 如何解释覆盖率

79.01% 是测试执行经过的 Python 可执行语句比例，不是“程序有 79.01% 正确”，也不能单独证明没有缺陷。

当前 PySide6 窗口代码没有在 pytest 进程中执行，因此该文件在覆盖率报告中为 0%；窗口背后的无界面 controller 已被测试，GUI 本身通过独立 offscreen smoke 检查。未来 GUI 行为增加后，需要加入更具体的交互测试，不能长期只依赖启动测试。

## 结论强度

这些证据支持以下结论：

- 在 M0 已声明的组合逻辑范围内，事件顺序具有确定性；
- NOT 的 Reference／Detailed／Fast 三模型对四态输入结果一致；
- 已提交状态变化能够形成具有时间和因果信息的可审计轨迹；
- 已记录实验能够通过重新计算检测输出或轨迹变化；
- GUI controller 与 CLI 使用同一个仿真事实来源。

这些证据不支持以下结论：

- 晶体管电压、模拟波形或 CMOS 电路已经正确；
- tick 等于真实纳秒，或延迟与任何实际器件一致；
- 时钟、寄存器和多驱动总线已经实现；
- M0 已经验证 CPU、Memory hierarchy 或 Attention；
- 79.01% 覆盖率等同于完整正确性证明。

ngspice 将在 M1 对选定的局部晶体管电路提供第三方交叉验证。
