# ADR 0002：固定传输延迟（Fixed Transport Delay）

- 状态：已接受
- 日期：2026-09-06
- 适用范围：M0 无内部状态、单驱动、固定延迟的数字组合逻辑

## 问题与依据（Problem and Ground Truth）

旧实现只在拟议输出不同于当前已提交值时才调度。若队列里还有未提交输出，
这个判断会漏掉必要的未来转换。初始输入为 1、输出为 0，delay=3，
在 t=7 输入 0、t=8 恢复 1，旧实现最终停在输入 1、输出 1。
若 t=9 再输入 0，最终值偶然正确，但 t=11、t=12 的波形仍缺失。

本次采用的依据是项目显式定义的数字传输规则：当次求值结果在固定延迟后提交。
单 NOT 的独立预期由字面真值表与时间平移生成；不以仿真器的实际输出构造预期。
这证明模型语义的符合性，不代表晶体管或某种 HDL 标准的全部时序语义。

## 决策与最小实现（Decision and Minimal Implementation）

删除求值阶段按当前值跳过输出的条件。每次求值输出都进入现有队列，
仅保留 `step()` 的提交时去重。沿用现有时间、delta、sequence 和 caused_by 字段。

不增加取消队列、版本令牌、延迟模式接口或新的运行时依赖。
稳定态交互继续调用 `set_input()` 和 `run_until_stable()`。
完整约定见 [数字逻辑规范](../specifications/digital-logic.md)。

## 代价与兼容性（Costs and Compatibility）

- 会增加没有实际变化的待处理项；它们仍推进时间、消耗事件预算和序号，但不进入变化轨迹。
- `Simulation.step()` 返回 `None` 也可能只是消费了一个无变化项，不等于队列为空；
  应读取 `pending_events`，或使用已有的 `Debugger.step()`／`run_until_stable()`。
- 无变化项会影响后续事件 ID 和因果引用；部分旧实验的摘要、结束时间可能变化。
  原有 `experiments/m0-not.json` 实测仍可原样重放，但不能据此保证所有旧记录都兼容。
- JSONL 和实验 JSON 的字段格式未变，schema 保持 v1。重放仍严格检测摘要差异；
  若旧记录失败，必须先核查完整波形并确认语义变化，不能自动覆盖预期来消除失败。
- 时间和预算的变化应视为此次行为修正的一部分。性能优化待测量后进行，
  且必须保留已声明的行为并明确处理轨迹兼容性。

## 验证与后续边界（Validation and Deferred Scope）

回归覆盖短于／等于／长于 delay 的输入间隔、同时刻输入、零延迟、重复值、X/Z、
两级 NOT 的四种零／非零延迟组合、因果链、确定性和重放。
另以 200 组生成序列比较完整波形，含延迟 0–5、四态初始值及最多 20 次输入请求。

暂缓惯性延迟、脉冲过滤、可变延迟、模拟电压、时钟／寄存器语义和真实硬件校准。
这些能力后续分别形成规格和测试，不扩张本次修复。
