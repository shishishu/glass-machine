# M0 架构：可信仿真闭环（M0 Architecture: Trustworthy Simulation Loop）

M0 建立 GlassMachine 最小但完整的可信闭环：

```text
Python 命令 / GUI 操作
          ↓
确定性仿真内核
          ↓
已提交的类型化事件轨迹
       ↙          ↘
调试 / 可视化       验证 / 重放
```

完整交付与验收结论见 [M0 完成与验收报告](../milestones/m0-completion-report.md)。

## 模块边界（Module Boundaries）

- `core` 定义四态逻辑、位宽、端口、组件契约和领域错误。
- `simulation` 拥有信号状态、事件队列和模型时间。
- `trace` 定义不可变事件以及版本化 JSONL 轨迹。
- `debugging` 通过仿真公开接口提供单步、探针和断点。
- `models` 先按领域／抽象层，再按模型角色保存模型；M0 使用 `models/digital/{reference,detailed,fast}/`。
- `experiments` 保存可序列化、可重算的实验配置。
- `validation` 比较独立模型，并给出明确的通过或失败结果。
- `visualization` 只读取仿真状态和轨迹，不拥有业务状态。

核心依赖方向是单向的：仿真核心不依赖可视化；CLI、GUI、实验和验证共同调用同一仿真 API。

`Simulation` 是模型无关的执行基础设施，不属于 Reference／Detailed／Fast 中的任何一种角色。当前 `digital/detailed/NotGate` 是由它执行的数字层详细模型；reference 和 fast 模型通过验证层与详细模型比较。

## 时间模型（Time Model）

事件按 `(time, delta, sequence)` 全序排列：

- `time` 是整数模型时刻，不是墙上时钟时间；
- `delta` 对同一模型时刻内的零延迟传播排序；
- `sequence` 是确定性的最终顺序号，用于打破同键事件之间的平局。

组件延迟是显式的非负整数。M0 不声称一个 tick 等于真实的一纳秒；物理单位和经过校准的时序配置属于后续层级。

## 状态所有权（State Ownership）

`Simulation` 拥有每个已提交的信号值。组件接收不可变的输入快照，并返回拟议输出；组件不能直接修改信号或可视化状态。

一次传播的基本过程是：

1. 外部输入或上游事件进入队列；
2. 内核按全序键选择下一事件；
3. 信号值通过位宽和驱动规则检查后提交；
4. 受影响组件读取输入快照并计算拟议输出；
5. 输出按组件延迟重新入队；
6. 每次真正提交的值变化产生一个 `TraceEvent`。

如果新值与旧值相同，则不制造虚假的状态变化事件。运行达到稳定态后才能创建稳定态快照。

## 因果轨迹（Causal Trace）

轨迹事件包含稳定事件 ID、`time`、`delta`、`sequence`、信号、位宽、旧值、新值、来源组件／端口、原因以及父事件引用。这样既能驱动界面，也能回答“谁在何时、因为什么改变了这个值”。

轨迹按版本化 JSONL 保存，并具有确定性 SHA256 摘要。摘要用于发现行为或轨迹格式变化，不用于替代逐事件诊断。

## 快照、调试与重放（Snapshots, Debugging, and Replay）

- 快照保存稳定态下的模型时间和信号状态，恢复后继续由同一内核运行。
- 调试器可以按事件单步，读取探针，并在指定信号变化时中断。
- 实验记录保存配置、期望输出和期望轨迹摘要。
- 重放会重新构造电路并重新计算，而不是播放旧动画；输出或轨迹摘要不同即判定失败。

## 当前范围（Current Scope）

M0 支持确定性的组合逻辑组件，并限制每个信号只能有一个驱动者。以下能力明确不属于 M0：

- 时序组件的 prepare／commit 语义；
- 时钟、锁存器、触发器和寄存器；
- 多驱动总线解析；
- 晶体管电压和模拟波形；
- 与真实硬件校准的时间和功耗。

四态逻辑已经作为基础类型存在，因此未来加入总线和时序逻辑时，不需要把二态数据结构整体推倒重写。
