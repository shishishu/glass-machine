# M0 architecture: trustworthy simulation loop

M0 establishes the smallest complete GlassMachine loop:

```text
Python command / GUI action
          ↓
deterministic simulation engine
          ↓
committed typed event trace
       ↙          ↘
debug/visualize    validate/replay
```

## Time model

Events are totally ordered by `(time, delta, sequence)`:

- `time` is an integer model-time tick, not wall-clock time;
- `delta` orders zero-delay propagation at the same model time;
- `sequence` is a deterministic tie-breaker.

Component delay is an explicit non-negative integer. M0 does not claim a tick equals a real
nanosecond. Physical units and calibrated profiles are later layers.

## State ownership

The `Simulation` owns every committed signal value. Components receive immutable input snapshots
and return proposed outputs. They cannot mutate signals or visualization state. The engine validates
widths, schedules output changes, commits them and emits `TraceEvent` records.

## Current scope

M0 supports deterministic combinational components with one driver per signal. Sequential
prepare/commit semantics, resolved multi-driver buses and calibrated physical timing belong to M1
and later milestones. Four-state values are already explicit so those extensions do not require a
binary-value rewrite.

## Replay

An experiment record stores its configuration, expected output and expected trace digest. Replay
reconstructs the circuit and recomputes the run. It does not merely play old events. A divergence
therefore detects behavioral or trace-schema changes.
